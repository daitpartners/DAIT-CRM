# Import leads + Data manager — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An "Import leads" page under Leads that turns messy Excel / CSV / PDF / Word / text files into staged rows, researches the missing details with the release-4 engine, imports only what a person approves (new companies, new contacts on existing companies, leads with the batch source), and a Data manager that lists every batch with downloads (CSV, highlighted "rows to fix" Excel), the original files, and Undo.

**Architecture:** Three new tables (`import_batches`, `import_files`, `import_rows`) hold everything until step 4. Uploads are stored under the shared storage folder; worker jobs read each file (`import_read_file`), research staged rows one at a time on the existing research lane (`import_research`, reusing `readWebsite` and the Claude Code runner), and import approved rows one row per transaction (`import_commit`), so every step survives a closed tab or a worker restart. One shared planner (`planBatch`) decides what step 4 shows and what the commit does, so the screen and the database never disagree.

**Tech Stack:** Fastify 5, Prisma 6 / PostgreSQL, existing jobs queue + worker lanes, `csv-parse` (already a dependency), new: SheetJS CE `xlsx` 0.20.3 (read .xlsx/.xls), `exceljs` 4.4.0 (write the highlighted .xlsx), `pdfjs-dist` 6.5.438 (PDF text), `mammoth` 1.13.0 (.docx text), `jszip` 3.10.1 (zip size guard, .docx page count); React 18 / Vite, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-24-import-leads-design.md` (binding) and the approved mockup `docs/superpowers/mockups/2026-11-24-import-leads.html` (screens, wording, classes). Read both before any task.

## Rulings (spec gaps decided here; owner may overturn)

1. **Batch is created when the first file is chosen**, and only after both radios are chosen (choosing files first shows the step-1 alert). Language / type can still be changed (PATCH) until Importing.
2. **Upload transport:** one file per request, `POST /api/imports/batches/:id/files?name=<file name>` with `Content-Type: application/octet-stream` (no multipart dependency; the CSRF origin guard still applies). Stored as `STORAGE_DIR/imports/<batchId>/<fileId>` (no user text in the path), mode 0600.
3. **Status "Ready" follows the spec**: company + known-or-unknown country + (email or phone or website). Research targets ticked rows with status "Missing details" only. (The mockup's sample rows label Brightline — which has a phone — "Missing details"; see owner questions.)
4. **Unknown country** (not in the CRM list) does not block "Ready" but carries an amber problem; such rows are imported only once the country is added ("Add these countries", Administrators → existing `POST /api/lookups`), otherwise left out and listed in rows to fix.
5. **Research values with "Accept" unticked are not facts anywhere**: company-field values (`website`, `city`, generic `email` → `businessEmail`) become suggestions; `industry` goes to `ai_industry` only when empty (AI's own classification, as release 4); contact-level values (contact name, designation, email, phone) and country are not written — they are listed in one lead timeline entry "Research found (not verified)" with source and confidence. Consequently, with the box unticked a row whose country or only contact method came from research is left out / counted under "Rows that still need you".
6. **Research counts:** a row whose research fetched a site or called Claude counts 1 toward the daily limit; a row with nothing to read (no website, Claude off) does not. When Claude is on and its cap is reached, research stops for the batch (spec text), even though the reader could continue. No automatic resume; Resume is manual.
7. **Not a lead:** a row with no company, email, phone or website; a repeated header row; a company cell starting with total / subtotal / grand total / totals / suma / total général (case-insensitive); a blank line between data rows (trailing blank rows are dropped).
8. **Unsure columns:** asked only for a column with a guess (weak alias, sniffed content, or a duplicate target). The guess is applied at once; Confirm with another field re-sorts that file's rows from their raw cells, keeping cells a person edited. Open questions never block the next step.
9. **Claude extraction (PDF / Word / text) keeps only values that occur in the source text** (normalised: case, whitespace, punctuation; phones by digits; websites by domain). Each chunk call counts toward the monthly cap; at the cap the rest of the file uses the deterministic extractor.
10. **Within one batch, rows of the same company share one company** (key = domain, else normalised name + country); each row still gets its own lead and contact.
11. **Commit is one transaction per row** (spec's "resumable chunks"), as a job; a row already imported is skipped on resume. Undo is one transaction per batch.
12. **Imports are quiet**: no per-lead "Review new lead" task or assignment notification; with the box ticked, one notification per assignee: `Import <number> · <n> leads assigned to you`, link `/leads?q=<number>`. Allocation by the existing rules (country + batch language).
13. **"Open leads in Leads list"** = `/leads?q=IMPORT-…`: the Leads search treats a batch number as an exact `import_batch` match (no new Leads UI).
14. **The Leads page "Import CSV" button and `CsvImportModal` are removed**; the old `/api/imports/leads*` endpoints stay for one release (listed in PENDING for removal). The new button "Import leads" shows only with `import_leads`.
15. **Batch number date** is the creator's local date; `-2`, `-3` … skip any number already used by a batch **or by `leads.import_batch`** (the CLI batches IMPORT-2026-11-21 / -22 exist).
16. **Retention:** original files are deleted 90 days after upload (Original files tab then says "Deleted after 90 days"); the batch and its rows stay as the record. A batch never imported is deleted entirely 90 days after its last change. Old CLI imports are not back-filled into the Data manager.
17. **Excel export colours** come from the app tokens: row fill `--bg` F5F1FC, red cell `--bad-bg` FDE8E8 / font `--bad-fg` A32020, amber `--warn-bg` FFF1E0 / font `--warn-fg` 8A4B00, header fill `--tint` EFE6FD bold; default spreadsheet font. Headers in the downloader's language; the header matcher knows all three languages.
18. **Large tables** (step 2, step 3, batch detail) page 100 rows with the existing `Pager` component.

## Review Focus

1. **Phone numbers stored as numbers in Excel** (971455501920, 4165550144, General format) → read as the full digit string, never "9.71456E+11" or "971455501920.0". (Task 2 test.)
2. **A sheet whose header is not on row 1** (title rows, a blank column, a second "Summary" sheet with totals) → header row found, totals and repeated headers become "Not a lead", nothing throws. (Task 3 test.)
3. **Re-importing the downloaded rows-to-fix file, including one downloaded in Spanish or French** → every column recognised with no unsure-column question, "What to fix" / "From" ignored, values land in the same fields. (Task 7 test.)
4. **The same company twice in one batch, or a row matching a company an earlier row of the batch created** → one company, two contacts, two leads; the unique `companies.domain` never fails a row. (Task 6 test.)
5. **A value starting with `=`, `+`, `-` or `@`** (exhibitor PDF, pasted sheet) → the CSV and Excel downloads never turn it into a formula (prefixed with `'`), phones like "+971 4 …" stay readable. (Task 7 test.)
